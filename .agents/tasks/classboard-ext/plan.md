# Implementation Plan — Class To-Do Board Extension (classboard-ext)

Derived from the FINAL `design.md` (do not redesign). Ordered by dependency. Each item leaves the repo buildable. Baseline is green: `npm run typecheck` passes and `npm run test` = 89 passed / 9 skipped (the RLS integration suite skips with a reason when the live-backend env is absent — that is the expected state in this worktree).

Project commands (from `package.json`, verified against the green base):
- Typecheck: `npm run typecheck` (`tsc --noEmit`)
- Lint: `npm run lint` (`eslint src`)
- Unit tests: `npm run test` (`vitest run`) — co-located `*.test.ts(x)`
- Build: `npm run build` (`tsc -b && vite build`)

Conventions to preserve (observed in the codebase, not assumptions): RLS is the sole authorization boundary (`mutations.ts` trusts RLS, no client role checks); `0001`'s ordering is enums → tables → `enable RLS` → table GRANTs → named role-explicit policies → publication/replica-identity; `is_officer()` is reused, never redefined; realtime hooks delegate to `useRealtimeTable` keyed on `id`; pure logic lives in `src/lib/*` with a co-located `.test.ts`; all colors are CSS tokens in `src/styles/tokens.css`; dialogs use the shared `Modal`; new per-mode color tokens go in `tokens.css` only (not `theme-core.ts`), like `--danger`.

Note on item ordering vs the spec: Navigation (design build-order step 5's infra) is pulled **before** Events here, because Events touches `TaskList`/`ScheduleCell`/`Layout` and Navigation refactors `Header` + wraps `Layout` in `App`; sequencing Nav first keeps each later item building against the final shell and satisfies the task instruction to sequence Navigation before Absences/Reviewers. The DB migration remains first.
